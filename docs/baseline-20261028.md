# OpenLoc baseline: 2026-10-28

## Status and purpose

Freeze the current implementation as a **diagnostic functional baseline** for
subsequent correctness, scenario and performance comparisons. This is not a
production release, calibrated accuracy baseline or real-time acceptance.
The preparation base is commit `d84d662`; this document describes the package
changes prepared on top of it, not an already-created commit or release tag.

The product goal remains indoor/outdoor multisensor localization: continuous
LiDAR/IMU ODOM, with optional wheel aiding and one selected global owner using
ODOM motion, GNSS, map and known-marker observations as available. An absolute
source must never initialize, correct, reset or replace local ODOM.
Reference frames, time, calibration, source dependencies and trust must remain
explicit. Losing absolute sources may legitimately reduce global precision or
availability; silent overconfidence or broken local continuity is not normal
degradation. See [principles](principles.md) and [architecture](architecture.md).

## Three separate responsibilities

| Layer | Current baseline | Still outside acceptance |
|---|---|---|
| Algorithms | `NativeOdometry` owns continuous local state. `FixedLagGlobalAlignment` is the target graph; map, position and heading observations use that owner. `BuildMarkerObservation` adapts associated surveyed-marker poses. | Marker detection/association, real sensor-model qualification and complete indoor/outdoor delivery. |
| Diagnostics | Source admission/correction decisions, pre-update innovation/NIS, provenance, freshness, trust ceiling and local/worker timing. `DiagnosticGlobalAlignment` remains an explicitly selected comparison owner. | Complete raw factor/robust-weight accounting, calibrated covariance and production consumer acceptance. |
| Offline evaluation | Maintained journal audit, whitening/correlation analysis, same-factor fixed-lag/batch and declared-model NEES tools, plus a 14-scenario executable matrix. | Independent physical accuracy, untested fault combinations, field labels and deployment budgets. |

Real raw map/GNSS replay evidence uses the diagnostic owner and, where declared,
diagnostic local tracking gain. It is not evidence that real data pass target
FixedLag admission. There is no implicit backend fallback.

Heading/position acquisition can explicitly return diagnostic XY/yaw with a
gravity-aligned-ODOM assumption; it does not invent height/roll/pitch or
initialize a complete SE(3) graph. Partial observations never renew full-pose
freshness. Graph retention after that lease expires remains default-off.
Public observation/result fields have changed since the preparation base;
downstream consumers must rebuild and check their source/trust contracts.

The matrix runs 24 nodes per case: 336 state rows, 498 observation outcomes and
386 recomputable NIS samples. Passing means the declared functional assertions
triggered, including degraded/unanchored outcomes, not that every case maintains
nominal precision.

Retained breadth covers 17 unique recordings, 36 arms, 34 completed diagnostics
and two startup failures; initial native ODOM starts in 15/17 windows.
Four recordings have actual map corrections, three have both map/GNSS
corrections. The retained ChengTou 180 s run has 1,702/1,800 local scan updates
and 407 map plus 126 GNSS corrections. These differing windows/settings must
not be pooled as a single acceptance score.

## Known blockers and performance boundary

Real native joint-model admission rejects nonunique voxel-assignment derivative
branches in three tested captures; ChengTou joint snapshots also exceed the
tested physical-memory limits. These are explicit model/capacity limitations,
not permission to substitute diagnostic covariance or relax admission.
Real marker data, shared map/survey error, timing/extrinsic qualification,
long-source-loss recovery and independent reference remain open. See the
[native error-model inventory](plan/native-lio-error-model-inventory.md).

The baseline includes exact batched map search, CSV field decoding optimization
and cached immutable world-point voxel keys. Factors, gates, scan windows and
floating-point accumulation order are not reduced to claim a speedup.
Retained final LIO comparison on ChengTou, three runs per side:

| Metric | Before voxel-key caching | Current |
|---|---:|---:|
| Nonpaced runtime LIO cumulative median | 1.605 s | 1.340 s |
| Median of per-run LIO P99 | 9.968 ms | 8.570 ms |
| Nonpaced total CPU median | 10.987 s | 10.972 s |
| 1x total CPU median | 13.511 s | 14.573 s |
| 1x valid ODOM over the 10 ms probe deadline, out of 4,071 | 169 / 195 / 250 | 260 / 238 / 296 |

This proves a local computation improvement, **not overall speedup**. Map cost
increased and its cause is unresolved; 1x CPU/deadline outcomes worsened.
The approximately 100 Hz local snapshot timer includes held measurements and
is neither fresh ODOM on every tick nor a Cyber/global consumer rate.
The previously observed 477 ms pause was not reproduced in this iteration.
No quota throttling was recorded during its 21 runs; that does not diagnose
the earlier pause. Short peak RSS does not qualify long-term memory behavior.

No independent truth is available for this field baseline. NIS/whitening can
expose contradictions, not certify covariance; batch uses the same factors,
and NEES conclusions apply only under declared synthetic error models.
Smoother output and same-source GNSS agreement are not accuracy evidence.

## Submission boundary and reproducible checks

Commit source, public/private headers, adjacent tests, `BUILD`, documentation,
agent rules and the small synthetic turning fixture in this independent
repository together. Include new untracked evaluators, marker files and
`exact_map_search.h`; a tracked-only commit would be incomplete.
Do not include raw recordings, maps/clouds, generated CSV/HTML, binaries,
logs or ignored investigation directories. Do not mix the independent Apollo
consumer or workspace/context repository changes into this package commit.
Preparation does not authorize staging, commit, tag, push or publication.

From the package directory **inside the managed container as the mapped
non-root user**, reusing existing caches:

```bash
env -u LD_LIBRARY_PATH bazel test -c opt \
  //:localization_algorithm_tests //:local_estimator_tests \
  //:native_odometry_tests //:localization_map_tests //:scan_to_map_tests \
  //:fixed_lag_global_alignment_test //:diagnostic_global_alignment_test \
  //:marker_observation_test //:online_gnss_quality_test \
  //:native_diagnostic_executor_tests //:native_motion_bootstrap_tests \
  //:online_localization_test \
  //:fixed_lag_evaluation //:localization_scenarios //:native_lio_replay
env -u LD_LIBRARY_PATH PYTHONPATH=test/integration/map python3 -m unittest \
  analyze_global_innovations_test evaluate_fixed_lag_test \
  evaluate_localization_scenarios_test evaluate_native_fusion_test
env -u LD_LIBRARY_PATH python3 test/integration/map/native_gnss_diagnostic_test.py \
  bazel-bin/native_lio_replay

env -u LD_LIBRARY_PATH python3 test/integration/map/native_map_diagnostic_test.py \

```

Commit-preparation results: 12 Bazel test targets pass, totaling 356 C++ cases
(eight targets reused valid cached results, four executed); three evaluation/
replay binaries build; 56 Python cases pass. The native Python CLIs require
the explicit executable argument: generic unittest discovery alone leaves
their class-level binary unset and is not the correct invocation.
The initial incorrect combined discovery failed for that reason and is not
counted as a pass. No dependencies were installed and no lint was run.
This is scoped regression evidence, not a complete code audit or full-package
test claim.

The portable summary is this document. Detailed local field artifacts are
intentionally ignored and must be obtained separately from the evidence owner.
The [local investigation index](../.agents/notes/README.md) locates frozen
reports and hashes when available; absence of those artifacts must not be
reported as reproduced field evidence.

## Next milestone

Keep this implementation/configuration frozen for comparisons. Prioritize:
real target-graph admission with explicit derivative/capacity outcomes; labeled
indoor/outdoor and real-marker source transitions; then controlled whole-pipeline
CPU/latency experiments that explain map cost and synchronous point-cloud
blocking. Independent-reference and consumer/deadline acceptance remain
separate gates. Do not optimize away degraded scenarios or change thresholds
to make the baseline pass.
